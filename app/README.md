# FastAPI-приложение Habr-Jev-Agent

Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2, SQLite WAL, httpx,
AsyncOpenAI, PyJWT, RapidFuzz и nh3. Без агентных фреймворков и внешней очереди.

## Локальный запуск

Все команды выполняются из директории `app/` репозитория. Нужны Python 3.12 и uv.

```bash
cp .env.example .env
chmod 600 .env
uv sync --frozen
uv run python -m app.main
```

В другом терминале из этой же директории:

```bash
uv run python -m app.worker
```

Настрой `.env`:

- `APP_ACCESS_TOKENS` — один или несколько длинных случайных токенов через запятую.
  При пустом списке все защищённые запросы отклоняются.
- `DEV_PROXY_KEY` — временный ключ HTTPS-прокси, передаётся только Laya и Gemma
  в `X-Dev-Key`. Ghost этот ключ не получает.
- `GHOST_URL`, `GHOST_ADMIN_API_KEY` — URL блога и полный Admin API key
  Custom Integration в формате `id:secret`. Content API key не подходит.
- `AUTO_PUBLISH=false` — проверка с сохранением черновика только в SQLite;
  запросов создания статьи в Ghost нет. Значение по умолчанию класса настроек —
  `true`, но пример и локальный файл намеренно используют `false`.
- `LAYA_BASE_URL=https://laya.yakvenalex-bypass.ru` и
  `LLM_BASE_URL=https://llm.yakvenalex-bypass.ru/v1` — режим разработки.

Полный список настроек и единицы измерения — в `.env.example`.
`APP_PORT` применяется запуском `python -m app.main`.
При запуске `uvicorn app.main:create_app --factory` порт задаётся отдельно uvicorn.
Если системный прокси мешает прямому соединению, добавь домены сервисов в `NO_PROXY`.

## HTTP API

Открой `/` в браузере: без сессии приложение перенаправит на `/login`.
Логин и пароль задаются в `WEB_USERNAME` и `WEB_PASSWORD`. Для `WEB_SESSION_SECRET`
сгенерируй случайную строку длиной минимум 32 символа. Реальные значения хранятся
только в локальном `.env`; публичного пароля по умолчанию нет.

После входа сессия сохраняется на `WEB_SESSION_HOURS` (по умолчанию 12 часов)
в подписанной HttpOnly-cookie с SameSite=Strict. Обновление страницы сохраняет
вход. Выход удаляет cookie. За HTTPS-прокси установи `WEB_COOKIE_SECURE=true`.

Главная страница использует Jinja2, обычный JavaScript и локальные CSS.
Можно заполнить пример, отправить новость, наблюдать категории Laya и вызовы
инструментов Gemma, открыть черновик и историю. Предпросмотр статьи изолирован
в iframe без разрешения исполнять скрипты. Пароль и ключи моделей не попадают в HTML.

Swagger доступен по `/docs` после входа, схема — `/openapi.json`. В браузере
Swagger использует текущую сессию; для API-клиентов остаётся **Authorize / Bearer**.
`/ready`, `/v1/news` и `/v1/jobs` принимают сессию браузера либо Bearer-токен.
Запросы с cookie, изменяющие данные, проверяют Origin. Статика, форма входа и
`/health` доступны без авторизации. Query-параметры для авторизации не используются.

Пример запроса (токен предварительно задаётся в переменной своего терминала):

```bash
curl http://127.0.0.1:8001/v1/news \
  -H "Authorization: Bearer $APP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "source": {
      "type": "manual",
      "name": "Example source",
      "external_id": "example-1",
      "url": "https://example.org/news/1"
    },
    "title": "Новая библиотека Python",
    "content": "Полный текст исходной новости с проверяемыми фактами...",
    "language": "ru",
    "published_at": "2026-10-23T09:00:00Z"
  }'
```

- `POST /v1/news`: до 20 000 символов `content`; время должно содержать timezone.
  Дополнительные поля запрещены. URL источника необязателен для приёма,
  но обязателен для публикации. Сеть для загрузки источника не используется.
- HTTP 200, `status=duplicate`: точное совпадение по нормализованному тексту,
  URL либо `(source.type, source.name, source.external_id)` до обращения к Laya.
  Уникальные ограничения защищают и от конкурентных запросов.
- HTTP 200, `status=skipped`: уверенно классифицированные `sports`/`world`.
- HTTP 202, `status=queued`: `technology`, `business` или неоднозначная классификация.
  Первоначальный запрос ждёт Laya, но не Gemma.
- HTTP 202, `reason=classification_retry`, `agent_started=false`: Laya недоступна
  или вернула некорректную структуру. Запись и задача уже сохранены, worker повторит
  классификацию. При падении API посреди запроса worker подхватывает задачу после lease.
- `GET /v1/news/{uuid}` — сохранённая новость, категория, вероятности, статус, причина.
- `GET /v1/jobs/{uuid}` — статус задачи, число шагов и попыток, ошибка,
  `publication_status` и `ghost_url`.
- `GET /health` — процесс жив; `GET /ready` — база, загруженная Laya, модель Gemma
  и Ghost Admin API (Ghost проверяется при `AUTO_PUBLISH=true`). При сбое HTTP 503.

Статусы задач: `queued`, `processing`, `published`, `skipped`, `failed`.
Проверенный материал в режиме dry run имеет `publication_status=dry_run`,
задача — `skipped`, причина — `auto_publish_disabled`.

## Публикация сохранённого черновика

При `AUTO_PUBLISH=false` интерфейс предлагает кнопку **Опубликовать черновик**
после завершения подготовки проверенной статьи. Нажатие вызывает защищённый
`POST /v1/news/{uuid}/publish`: задача этой новости повторно ставится в очередь
с сохранённым намерением `publish_requested`, а в журнал добавляется событие запроса.
Изначальная подготовка и новый проход агента остаются в одном журнале.

Gemma получает исходник и сохранённый текст, проверяет соответствие фактов и тему,
вызывает поиск дублей, затем `publish_article`. Переписывание статьи в этом режиме
недоступно. Приложение повторно классифицирует текст через Laya, проверяет HTML,
источник, лимиты и дубликаты. Разрешение касается только выбранной статьи и
позволяет отправить её в Ghost при выключенной **автоматической** публикации.
Остальные новости по-прежнему создают черновики.

Повторное нажатие возвращает уже запущенную задачу, а для опубликованной статьи —
существующую ссылку без повторной отправки. Неопределённые отправки `submitting`
этим действием не сбрасываются. В Ghost создаётся общедоступная статья
(`status=published`, `visibility=public`), в интерфейсе появляется **Открыть в блоге**.
Модель может отказаться от публикации с причиной; декларации модели не заменяют
независимой фактологической проверки.

## Очередь и публикация

API атомарно сохраняет новость и задачу восстановления перед сетевым запросом.
Worker выбирает задачу под `BEGIN IMMEDIATE`, выдаёт уникальный lease token и
продлевает lease heartbeat-ом. Просроченную задачу можно забрать после перезапуска;
старый worker теряет право выполнять инструменты. Повторы ограничены
`JOB_MAX_ATTEMPTS`, между ними предусмотрена короткая задержка. Один worker
обрабатывает задачи последовательно; конкурентное получение также защищено.

Harness ограничивает число ответов модели, число инструментов в ответе и общее
время выполнения. Допущены ровно четыре инструмента с Pydantic-схемами:
`get_source_context`, `find_similar_news`, `save_article`, `publish_article`.
Идентификаторы новости и целевой Ghost фиксирует приложение. Нет выполнения shell,
Python, браузера или произвольной загрузки URL.

Прежде чем сохранить статью, модель должна запросить источник и похожие новости.
Приложение отклоняет материал, если нужны дополнительные подтверждения, нет
первоисточника, получился пустой HTML или повторная классификация статьи не дала
`technology`. nh3 удаляет опасные теги, атрибуты и URL-схемы. Источник добавляется
программно с экранированием. Перед публикацией поиск опубликованных похожих
материалов повторяется независимо от аргументов модели.

Сходство считается по нормализованным заголовкам и текстам RapidFuzz.
`SIMILAR_NEWS_THRESHOLD`, `ROUTING_MIN_PROBABILITY`, `ROUTING_MIN_MARGIN` — эвристики;
их нужно проверять на размеченных примерах. Они не являются оценкой точности.
Просмотр истории для сходства имеет линейную сложность — достаточно для MVP.

До отправки POST в Ghost сохраняется `publication.status=submitting` и
резервируется место в часовом лимите. Статья имеет стабильный slug `jev-<news_uuid>`.
После сетевой ошибки выполняется поиск по slug. Следующая попытка для `submitting`
может только подтвердить публикацию, повторный POST запрещён. Это предотвращает
двойную отправку, но может потребовать ручной сверки, если процесс упал после
резервирования и до POST. В этом случае задача после повторов станет `failed`,
а статья останется `submitting`; проверь блог по slug прежде чем менять состояние.
Нельзя просто сбрасывать такую запись в `draft`.

Лимит считает все попытки отправки за последний час, включая неопределённые;
это консервативнее подсчёта только подтверждённых публикаций. Успешная публикация
останавливает цикл сразу, без дополнительного ответа модели.

Полный JSON Laya сохраняется в `news.laya_response`, в том числе ответ с
некорректной схемой, если он является JSON-объектом. След инструмента
содержит названия, шаги и статусы; без секретов и без сырых ошибок внешних сервисов.
Исходный текст и статьи хранятся в базе. SQLite хранит время в UTC без timezone.

## Ограничения проверки фактов

Без внешних проверенных источников программа не доказывает фактическую корректность
текста. Источник считается идентифицируемым при наличии корректного HTTP(S) URL;
доступность и достоверность этой страницы автоматически не проверяются.
Инструкции требуют атрибуции, запрещают выдуманные факты и заставляют модель
обозначить необходимость проверки. Эти декларации и тематический классификатор
не гарантируют отсутствие галлюцинаций или prompt injection. При недостаточных
данных модель должна отказаться; для оценки качества нужен отдельный набор кейсов.

## Docker Compose на сервере

Сначала запусти существующие проекты `laya/`, `llm/`, `blog/` по их настройкам.
Создай общую сеть, если её ещё нет:

```bash
docker network create agent-net
```

В `app/.env` измени только настройки:

```dotenv
LAYA_BASE_URL=http://laya:8000
LLM_BASE_URL=http://llm:8080/v1
DEV_PROXY_KEY=
GHOST_URL=https://your-blog.example.org
GHOST_ADMIN_API_KEY=your-id:your-secret
AUTO_PUBLISH=true
```

```bash
docker compose up -d --build
docker compose logs -f api worker
```

API и worker используют один именованный volume `agent-data` для SQLite, включая
файлы WAL/SHM. Порт API привязан к loopback; внешний доступ настраивается через
reverse proxy. Сервисы моделей разрешаются по DNS в существующей `agent-net`.
Ghost доступен по настроенному URL; его Compose менять не требуется.
Образы работают от пользователя без root. `.env` и локальные данные не входят в build.

Схема создаётся автоматически на чистой базе. Для существующей базы предусмотрено
идемпотентное добавление `jobs.publish_requested` под `BEGIN IMMEDIATE`, без потери
новостей, черновиков и журнала. Для остальных изменений схемы нужны отдельная
миграция и резервная копия.
Для простого консистентного бэкапа останови оба процесса, затем сохрани volume.

Разработческие HTTPS-поддомены и их Nginx-конфигурацию после перехода на внутреннюю
сеть нужно отключить на сервере. Это приложение не меняет Nginx и не открывает модели.

## Проверки

```bash
uv run ruff check app tests scripts
uv run ruff format --check app tests scripts
uv run pytest -q
```

Автотесты используют временные SQLite и фиктивные Laya/Gemma/Ghost. Покрыты
авторизация, валидация, маршрутизация, точные дубли и конкурентные запросы,
tool calling, ошибки сервисов, лимиты, очистка HTML, восстановление lease,
повторные попытки и неопределённый результат отправки в Ghost.

Ручной интеграционный тест вызывает настоящие Laya и Gemma из `.env`, включая tool call,
но не публикует в блог:

```bash
RUN_MODEL_INTEGRATION=1 uv run pytest -q tests/test_integration.py
```

Изолированный прогон всего worker с настоящими моделями на фактах из документации Python:

```bash
uv run python scripts/smoke_models.py
```

Этот скрипт принудительно использует `AUTO_PUBLISH=false`, временную базу и не создаёт
публикаций в Ghost. В следе видны вызовы инструментов и ограниченные коррекции протокола.

Полный прогон с настоящими моделями сначала выполняй при `AUTO_PUBLISH=false`.
Тест реального создания статьи выполняй только с отдельным тестовым Ghost-блогом.
Ключи и настоящие токены нельзя включать в Git, логи и примеры запросов.
